# Поддерживаемые клиентские протоколы

## VLESS

Текущий парсер принимает одиночные `vless://` URI и HTTPS-подписки в plain text или Base64. Поддержаны:

- RAW/TCP без TLS;
- RAW/TCP + REALITY, включая Vision;
- XHTTP + TLS;
- XHTTP + REALITY.

Неизвестные query-параметры отклоняются. Это намеренная строгая проверка: приложение не должно молча импортировать конфигурацию с потерянной семантикой. Имя после `#` служит только для отображения и не определяет идентичность узла.

Узлы подписки различаются по канонической совокупности endpoint, UUID, транспорта, security, flow, SNI, fingerprint, REALITY-параметров и XHTTP host/path/mode/padding. Исходный URI и отображаемое имя исключены. Поэтому два URI для одного host/port/UUID с разными транспортами или XHTTP path сохраняются как разные узлы.

Для REALITY отсутствующий fingerprint получает совместимое значение `chrome`. Явный fingerprint принимается только из поддерживаемого списка Xray. URL подписки обязан быть публичным HTTPS URL; private, loopback, link-local, multicast, CGNAT и IPv4-mapped варианты таких адресов отклоняются при каждом соединении и redirect.

## AmneziaWG

Конфигурация AmneziaWG разбирается и проверяется отдельно, но подключение пока заблокировано. На тестовом LXC нет `/dev/net/tun`, совместимость kernel module не подтверждена, а изменение default route запрещено до отдельного review Safe Apply/watchdog.

## Обновление подписок

Допустимы интервалы `disabled`, `6h`, `12h` и `24h`. `StartScheduler(ctx)` выполняет одну отменяемую process-lifetime петлю и сериализует автоматическое обновление с ручным refresh. `last_update_at` хранит время последней попытки, включая неудачную; результат и безопасная причина доступны отдельно в `update_status` и `last_error`. Это не позволяет недоступной подписке повторяться каждую минуту.

Массовая асинхронная проверка всех узлов с прогрессом SSE пока не реализована. Одиночные тесты ограничиваются общим semaphore не более пяти процессов. При редком одновременном PATCH узла и refresh подписки сохранение пользовательских `favorite/enabled` требует дополнительной атомарной проверки в storage transaction.
