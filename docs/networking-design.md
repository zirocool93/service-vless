# Проект сетевого управления — ожидает отдельного review

Сетевой контроллер ещё не реализован. Этот документ фиксирует обязательные вопросы до начала Phase 5 и до любого AWG-подключения, которое изменяет default route. Решения по пакетному пути и конкретным правилам будут внесены после проверки в Linux namespaces и Ubuntu VM; отсутствие таких решений запрещает реализацию маршрутизации.

Для review нужны: схемы входящего и исходящего пути IPv4/IPv6; выбор fwmark, policy routing tables и nftables chains; прямой маршрут до VPN endpoint; исключения LAN, активного SSH и панели; DNS и предотвращение IPv6-утечек; взаимодействие с уже существующим firewall; процедура восстановления после падения процесса/перезагрузки. Все идентификаторы должны быть отдельными от правил других программ, существующие таблицы нельзя очищать целиком.

Порядок изменения сети: проверить входные данные и применимость → снять snapshot маршрутов/firewall/DNS и надёжно сохранить его на диске (`fsync`) → вооружить **независимый** watchdog с указанием snapshot и получить подтверждение → только затем выполнить первую мутацию → проверить VPN, интернет и доступ управления по IPv4/IPv6 → подтвердить результат или откатить snapshot. Если snapshot не сохранён или watchdog не подтверждён, изменение не начинается. Этот документ пока содержит вопросы и порядок review, а не утверждённый packet-flow design. Критерии review и приёмки приведены в [плане](implementation-plan.md); реализация и результаты VM-проверок отсутствуют.
