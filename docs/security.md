# Безопасность

Production web-интерфейс использует self-signed TLS не ниже 1.2. Начальный пароль администратора генерируется отдельной командой `init` и один раз выводится в stdout installer, а не journald. Пароли хешируются Argon2id; в SQLite хранятся только hash сессионного токена и зашифрованные AES-256-GCM секреты. Потерянный `master.key` при существующей БД не заменяется автоматически.

Cookie имеет `HttpOnly`, `Secure`, `SameSite=Strict`. API проверяет сессию; мутации требуют `X-CSRF-Token` и same-origin. Login принимает строгий JSON, проверяет Origin/Sec-Fetch-Site и использует bounded per-IP limiter до Argon2. SSE периодически повторно проверяет действительность сессии.

## Full Tunnel

Full Tunnel разрешён только на production Linux от root с systemd и установленным независимым watchdog. Prepare не меняет сеть. Apply принимает одноразовый token, связанный с transaction ID, hash, cookie-сессией и фактическим `RemoteAddr`; `X-Forwarded-For` не считается management peer. Confirm принимается от той же сессии/peer только до 120-секундного deadline и после TCP, DNS UDP/TCP и IPv6-block checks.

Watchdog вооружается и durable подтверждается до сетевых изменений. Затем backend устанавливает только tracking conntrack hooks и фиксирует разрешённые management tuples; прежде чем добавлять route/rule и публиковать intercept, независимый watchdog проверяет durable ACK seal. При изменениях после commit watchdog продолжает проверять seal. Смерть watchdog, backend или отдельного Full Tunnel Xray вызывает rollback. Если durable commit ACK отсутствует, confirm возвращает ошибку и запускает rollback. Early boot recovery запускается до backend, а `ExecStartPre` вызывает его перед каждым backend start/restart. Snapshot и manifest имеют root-only права и hashes; PID проверяется вместе с process starttime и boot ID. Reboot acceptance подтвердила выполнение recovery на Ubuntu LXC и сохранение direct-состояния.

Sandbox backend не получает `CAP_SYS_PTRACE`. Поскольку `/proc/1/ns/net` может возвращать `EPERM`, root pre-start recovery создаёт `host-netns.json` с host namespace identity и boot ID. Backend сравнивает этот durable proof со своим namespace и текущим boot ID; он не доверяет proxy-заголовкам или недоступному proc PID 1. Для transparent TCP/UDP listener недостаточно `CAP_NET_ADMIN` и `CAP_NET_RAW`: VM-проверка получила `EACCES` (`errno 13`) при bind без `CAP_NET_BIND_SERVICE` и успешный bind после его добавления. Поэтому capability явно выдана backend и порождённому Full Tunnel Xray; `CAP_SYS_PTRACE` по-прежнему не требуется.

Staging отвергает обнаруженные чужие marks, `notrack`, conntrack zones и flow offload до своих сетевых изменений. Snapshot `ss -Hnt state all` включает только established, SYN-RECV и активные closing TCP-состояния для peer management и портов SSH/UI; LISTEN и SYN-SENT не включаются. Write-once flow set и seal содержат полный local/remote IP+port tuple, привязаны к manifest hash и требуют независимого durable ACK. Точный tuple bypass предшествует conntrack reply правилу; новые ответы всё равно проходят peer/source-port/state/direction условия.

Внешний IPv6 блокируется до bypass mark. DNS port 53 перехватывается до LAN исключений. Dokodemo `followRedirect: true` передаёт запрос в freedom `uvg-dns-rewrite`, который переназначает его на `1.1.1.1:53` и через `proxySettings.tag: "proxy"` не допускает direct DNS. Endpoint bypass ограничен точным IPv4+port. Приложение не flush-ит чужой nft ruleset и не меняет sysctl/resolver. Rollback удаляет владельческую table; если это не удалось, он best-effort очищает обе output/prerouting chains и снимает маршруты и Xray лишь после доказанного отключения intercept. Неполная очистка фиксируется как `rollback_failed`, а зависимости сохраняются для безопасной повторной попытки.

Root namespace acceptance пройдена, включая dummy-source sysctl-сценарий; production sysctl при этом не менялись. Standalone и chained TCP/UDP DNS проверки прошли после добавления `CAP_NET_BIND_SERVICE`. Основной VM-цикл достиг `pending`: все checks успешны, обычный `curl` вышел через VPN с IPv4 `89.125.93.116`, DNS UDP/TCP из LAN прошёл, новые SSH и HTTPS-соединения подтвердили active-состояние. `disable` вернул HTTP 200, точный nft baseline стал пустым, hashes DNS/TLS/master-key не изменились.

Если Manager стартовал без in-memory plan, status читает durable recovery journal без сетевых мутаций и не маскирует незавершённую запись как `disabled`. При corrupt manifest наружу остаются transaction ID и `rollback_failed`, но `plan` не раскрывается; `available=false` сообщает UI о недоступности prepare. Аутентифицированный `disable` повторно запускает recovery, а его ошибку нельзя принять за успешный fail-open.

Staged management-flow acceptance прошла: namespace сохранил существующий полный 4-tuple и новый TCP flow между capture/publish; VM сохранила heartbeat старого SSH и приняла 12 новых SSH-подключений во время Apply. Ошибки процессов watchdog/backend/Xray, lease expiry, reboot и update проверены, чужие nft/routing объекты сохраняются. Опубликованная `v0.2.0` прошла CI на Go 1.26/1.27; release workflow создал amd64/arm64 archives и checksum manifest. Публичное обновление active Full Tunnel VM до `v0.2.0` сохранило DNS/master/TLS hashes; повторный Apply/Confirm на публичном бинарнике завершился со всеми checks успешно. Docker routing, kill switch и AWG runtime не входят в текущую модель безопасности.
