### VM-приёмка Full Tunnel: найденные проблемы и коррекции

- Сформирован bundle-кандидат v0.2.0 для amd64/arm64; release ещё не опубликован. Штатный installer обновил Ubuntu VM с v0.1.1 с сохранением master.key, TLS и импортированных узлов. Network namespace acceptance повторно пройден на финальном helper перед основной сетью.
- Restricted capabilities systemd запрещают backend readlink `/proc/1/ns/net`, хотя namespace совпадает. Проверка заменена boot-bound durable host-netns.json от успешного recovery, без добавления CAP_SYS_PTRACE. Backend доступность после повторной штатной установки подтверждена.
- Первая основная транзакция получила independent armed ACK до мутаций, но DNS UDP не прошёл. Автоматически удалены nft intercept и policy rule, SSH/HTTPS доступны, direct IP восстановлен. Хеши resolv.conf, master.key и TLS совпали с baseline.
- При проверке полного cleanup выявлен оставшийся local route table200: iproute2 показывает protocol186 строкой bgp, а сравнение ожидало186. Удалён только известный local default devlo table200 proto186; оригинальные маршруты и чужие nft не затронуты. Review и regression tests исправления numeric JSON продолжаются; частичный cleanup не считается полной успешной приёмкой.
- По pinned Xray source установлен дефект DNS inbound followRedirect=false: UDP reply не forged от исходного DNS. До повторного применения выполнено отдельное уточнение сетевого design/review: followRedirect=true и freedom redirect с обязательной цепочкой через VLESS. Ожидается проверка реальным UDP/TCP запросом и packet capture; текущая VM acceptance ещё не завершена.

- Dummy-source namespace test воспроизвёл интерфейсный источник VM с rp_filter=2/accept_local=0 и прошёл. Sysctl VM не менялись. Отдельный systemd bind diagnostic подтвердил отказ errno13 для transparent UDP bind :53 при исходных caps и успех с CAP_NET_BIND_SERVICE. После отдельного review в backend unit добавлена только эта capability; watchdog/recovery без расширения caps.
- Следующая VM-транзакция прошла все внутренние проверки и была отдельно подтверждена через новый HTTPS-сеанс. Обычный curl без --proxy и DNS UDP/TCP к LAN resolver показали VPN-путь; внешний IPv4 89.125.93.116. Новые SSH/HTTPS доступны, explicit disable вернул 194.186.91.130, nft baseline совпал, table200 пуста, хеши DNS/master/TLS неизменны.
- Обнаружена проблема прежнего HTTP-сеанса Apply: его ответ не доставлен, хотя новые управляющие сеансы доступны. Вероятная причина — conntrack включён только с установкой ruleset, и старый TCP flow впервые наблюдается как original вместо reply. Приёмка сохранения уже открытых соединений не пройдена; выполняется отдельное review точных management TCP tuples до следующего применения. Опубликованный release v0.1.1 пока остаётся последним.
